# Очистка данных сессий и аккаунтов

Удаление сразу закрывает сессию и очищает текущие объекты S3. Если для неё
выдавались подписанные `PUT`, база сохраняет только идентификаторы владельца
и сессии и сроки дополнительной очистки. Запись переживает удаление аккаунта.

Расписание Eve `late-uploads` каждые пять минут обрабатывает дозревшие записи.
Первый проход удаляет только префикс `uploads/` после истечения срока подписи
с минутным запасом. Второй проход через сутки после истечения подписи убирает
загрузки, начатые до истечения, но завершившиеся позднее. Сбой S3 или остановка
процесса оставляет запись для следующей попытки. Хост должен запускать
расписания Eve: в локальном `eve dev` они доступны только по ручному вызову
`POST /eve/v1/dev/schedules/late-uploads`. Для нестандартного продакшен-хоста
нужен собственный планировщик, вызывающий ту же функцию.

Подписанный URL не отзывает уже принятый хранилищем запрос. Для гарантии за
пределами суточного запаса ограничьте полную длительность `PUT` на стороне
хранилища или его входного прокси. Очистка работает с текущими объектами;
версионирование и незавершённый multipart требуют отдельных правил S3.

В Daytona приложение сохраняет привязку к ключу до отправки запроса на создание
и хранит известные идентификаторы машин отдельно от текущей песочницы.
Удаление обращается только к этим машинам: по ID, а если создание не успело
записать ID — по детерминированному имени. Перед удалением сверяется точная
метка `studio_session`. Если исходный ключ отозван, не хватает прав или секрет
недоступен, приложение пробует ключи той же известной организации. Если ни один
из них не подходит, сессия остаётся помеченной для повторной попытки. Недоступность
других организаций не мешает удалению.

При миграции сохраняется привязка из текущей строки песочницы. Если до миграции
машина уже потеряла эту привязку и осталась в очереди `pending_sandbox_deletions`,
её по-прежнему обрабатывает удаление ключа. Если в базе не осталось связи машины
с сессией, автоматическая очистка не пытается угадать её организацию.

## Данные Eve Workflow

Штатная установка использует Eve 0.83.0 и общий с Next.js каталог `.eve` с
локальным Workflow World 5.1.2. После блокировки сессии приложение находит
её запуски и связанные запуски по сохранённому владельцу, привязке Eve и
отношениям между сессиями, копиями и workflow-инструментами. Прежде чем
очищать файлы, приложение сбрасывает активные сессии и ждёт завершения всей
цепочки. Вместе с содержимым запусков очищаются относящиеся к ним локальные
трассы и индексы.

World сохраняет короткую терминальную запись без текста, настроек и ссылки
на владельца. Она нужна, чтобы отложенная доставка не восстановила сессию.
До первой очистки приложение записывает на томе `.eve/.workflow-data` список
всех проверенных запусков. Повтор использует этот список, даже если часть
записей уже очищена и не содержит связей с дочерними запусками. У каждого
известного идентификатора Eve должен быть корневой файл на томе; терминальная
запись без данных владельца принимается только вместе с журналом этой сессии.
Если том не тот или на нём нет ранее проверенных запусков, запрос не выдаёт
успех. После удаления строки сессии и финальной очистки S3 приложение удаляет
временный журнал. Терминальные записи и файлы соседних сессий сохраняются.

Если запрос создания сессии был принят, но корень так и не привязался в базе,
приложение ищет его по сохранённому владельцу. Оно не считает отсутствие корня
подтверждением, что создание не произошло: сессия остаётся скрытой, а удаление
можно повторить после появления корня или восстановления правильного тома.
Запросы создания, которые точно не дошли до Workflow, требуют сверки оператором.

Формат файлов локального World привязан к версии. Перед обновлением Eve или
хранилища проверьте приёмку удаления на копии состояния. В штатной production-сборке
Next.js и Eve 0.83.0 Nitro может записать в `version.txt` имя своего манифеста
`traced-node-modules@1.0.0` вместо версии World. Приложение принимает этот маркер
только для стандартного локального каталога и совпадающего манифеста Nitro;
проверки формата файлов и корневых запусков не меняются. Для раздельного
развёртывания Eve или другого Workflow World нужен отдельный адаптер:
приложение не сообщает об успешном удалении, если не может проверить и
очистить хранилище. Сохраняйте и подключайте `.eve/traces` к одной постоянной
записываемой директории во всех релизах, помимо тома `.eve/.workflow-data`.
Если прежние релизы хранили локальные трассы у себя, перенесите их в общий
каталог либо удалите по политике хранения до вывода старых релизов из работы.
Адаптер читает только активный каталог трасс; архивы, резервные копии и внешние
системы трассировки регулируются политикой хранения оператора.
