# Проверка кадров

Проверяй изображение глазами через `read_file`, не делай вывод о качестве
по исходному коду или успешному завершению команды. Для проверочных кадров
этот навык имеет приоритет над PNG из официального `remotion-render`.

## 1. Опорные кадры

Прочитай `NOTES.md` проекта; при первом создании используй
[шаблон заметок](references/notes-template.md). Обнови таблицу сцен после
изменений. Начало и конец сцены — абсолютные номера кадров, оба включительно;
для переходов учитывай перекрытие сцен, а не складывай их длительности вслепую.
Секунды переводи в кадры как `round(секунды × fps)`.
Прочитай фактические тайминги композиции: `from`, `durationInFrames`, интервалы
анимаций и переходов. Вычисли конец сцены как `start + durationInFrames − 1`
с учётом вложенных смещений и перекрытий; сверь с таблицей сцен.
Для проверки конечного состояния выбери реальный кадр после завершения
входной анимации и до начала выхода или перехода, а также последний кадр сцены,
если важен её выход. Кадр на 85 % — только выборочная точка, не доказательство
достижения конечного состояния. Если интервала установившегося состояния нет,
проверяй фактическую границу анимации внутри сцены, не выдумывай остановку.

За проход выбери **4–8 разных кадров** (если весь ролик короче четырёх кадров,
посмотри все). Составь кандидатов:

- кадр `0` и последний `durationInFrames − 1`;
- для каждой сцены `[start, end]`: `start + round(0.25 × (end − start))`
  и `start + round(0.85 × (end − start))`;
- середина каждого перехода;
- самый плотный кадр: максимум одновременно видимых текста и элементов.
- Для субтитров — кадр с самой длинной страницей и кадр на границе двух
  фраз по таймингам `voiceover`; эти два кадра обязательны наравне с 0,
  последним и самым плотным при отборе в пределах 4–8 кадров.

Округли номера, ограничь диапазоном композиции и убери дубликаты. Если кадров
меньше четырёх, добавь равномерные точки всего ролика. Если больше восьми,
отбирай в следующем порядке, прекращая добавление на восьми:

1. Кадр `0`, последний, самый плотный, а при субтитрах ещё самая длинная
   страница и граница двух фраз — обязательные, дубликаты занимают одно место.
   После них добавь прежде других кандидатов кадры изменённых
   сцен и затронутых переходов: сначала ранее проблемные кадры, затем новая
   вёрстка и самый плотный текст; при равном риске — равномерно по хронологии.
2. Кадры около 25 % сцен. Если все сцены не помещаются, выбери сцены равномерно
   по хронологии из ещё не представленных: при `m` сценах и `k` местах возьми
   индексы `round(j × (m − 1) / (k − 1))`, `j = 0…k − 1`; при `k = 1` — среднюю.
   Это выборка, а не обещание показать каждую сцену в одном проходе.
3. Если места остались, добавляй по очереди кадр около 85 % следующей сцены
   и середину следующего перехода, в хронологическом порядке.

Сохрани выбранные номера и причины в `NOTES.md`. Сортируй итоговый список
по возрастанию. При множестве сцен это проверка выборки, а не каждой сцены:
лимит остаётся 4–8 кадров на проход. После правки выборку сосредоточь
на затронутых сценах и переходах по приоритету выше. Известный дефект нельзя
пропустить ради лимита: если все проблемные кадры не помещаются, сначала
упрости число сцен или вариантов вёрстки, затем проверь новую выборку.

## 2. Рендер кадров

Все команды выполняй из каталога проекта. Укажи фактические входной файл,
идентификатор композиции и список номеров; `N` — новый номер каталога при
каждом запуске, включая повторную проверку после правки:

```sh
npx remotion render <вход> <композиция> out/frames-N --frames=<список> --image-format=jpeg --jpeg-quality=90
ls out/frames-N
```

Для одного проблемного кадра допустимо:

```sh
npx remotion still <вход> <композиция> out/frames-N/check.jpeg --frame=<номер> --image-format=jpeg --jpeg-quality=90
```

Всегда выбирай новый каталог `out/frames-N`, старые кадры не удаляй командой
`rm -rf`. Remotion каталог не очищает. Имена `element-<кадр>.jpeg` дополняются
нулями до ширины наибольшего номера выбранного набора: при `0,30,89` получится
`element-00.jpeg`, а при `0,30,899` — `element-030.jpeg`. Бери реальные имена
из `ls`, а не угадывай их и не смотри кадры предыдущей версии.

Перед любым просмотром проверь пиксели **всех выбранных кадров** скриптом
этого навыка (Pillow уже есть в образе песочницы):

```sh
python3 "$HOME/.agents/skills/frame-review/scripts/check-frames.py" out/frames-N/*.jpeg
```

Для PNG укажи `*.png`; при повторной проверке перечисли актуальные файлы
явно. Скрипт только читает исходные изображения. Код 1 означает однотонный
или почти чёрный кадр, код 2 — ошибку чтения или аргументов. Запиши дефект
в `NOTES.md`, исправь композицию и перерендери затронутые кадры в новый каталог.
Вход и выход сцен должны оставлять видимое содержимое на кадрах 0 и последнем;
проверь также затухание контейнеров, содержащих всю сцену.
Неудачная проверка пикселей расходует тот же проход из раздела 5.
После кода 0 просмотри все актуальные выбранные кадры через `read_file`,
включая 0 и последний. Нормальный диапазон пикселей означает лишь отсутствие
очевидного пустого кадра, а не визуальное качество или готовность ролика.
Уменьшать выборку, подменять изображения или считать статистику просмотром нельзя.

## 3. Ограничения просмотра

`read_file` показывает PNG, JPEG, GIF и WebP не больше **3 МиБ (3145728 байт)**
и **8000 пикселей по каждой стороне**; при превышении лимита инструмент бросает
ошибку с просьбой уменьшить или обрезать изображение, а не возвращает картинку.
Проверь размеры и вес, если изображение не показано. При любой стороне
больше 4000 пикселей добавь к рендеру кадров `--scale=0.5`; если результат
всё ещё превышает ограничения, уменьши масштаб дополнительно. Масштаб
проверочных изображений не меняет заказанное разрешение полного видео.

JPEG — основной формат. PNG допустим только для проверки резкости мелких
деталей; сначала проверь `stat -c%s <файл>`. При превышении лимита пересоздай
кадр в JPEG или с меньшим масштабом и добейся ответа с картинкой.

## 4. Просмотр

Вызови `read_file` для каждого выбранного файла (можно параллельно).
Для каждого кадра проверь все пункты:

- Текст целиком внутри кадра, не обрезан; нет случайных переносов и опечаток.
- Безопасная зона: при ширине 1080 px — минимум 80 px по бокам и 100 px
  сверху и снизу. Заголовок не меньше 84 px, важный поясняющий текст — 44 px.
  Все числа масштабируй на `ширина композиции / 1080`, как в
  `remotion-create/video-layout.md`; уменьшенный просмотр учитывай отдельно.
- Элементы не перекрывают друг друга, текст контрастен и читается на фоне.
- Нет пустых и чёрных кадров, «тофу» вместо букв, пропавших эмодзи
  и сломанных изображений.
- На вычисленных конечных границах анимация показывает задуманное: отрендери
  эти реальные кадры и просмотри через `read_file`. При необходимости замени
  ими точки 85 % в пределах лимита 4–8; произвольный процент не заменяет
  проверку конечного состояния и выхода сцены.
- Соотношение сторон и исходные размеры композиции совпадают с заказом.
- Субтитры занимают максимум две строки в безопасной зоне, размер не ниже
  нормы поясняющего текста; есть контрастная подложка/обводка и выделение
  текущего слова. Сверь кадр со временем слова, допуск ±150 мс.

Запиши результат каждого кадра и конкретные дефекты в `NOTES.md`.

## 5. Исправление и предел попыток

При квадратах вместо букв сначала прочитай точную строку из исходника:
сверь её символы, слова и язык с задуманным текстом. Исправь случайные символы
или чужое слово через `edit_file`; шрифт и его загрузку проверяй, только если
исходная строка верна. После исправления просмотри заново отрендеренный кадр.

У проверки кадров и правила «три попытки исправить одну проблему» один
счётчик в `NOTES.md`: **не больше трёх проходов**, не три плюс ещё три.
Первый набор кадров — проход 1, включая проверку пикселей и просмотр.
Перед каждым следующим рендером прочитай счётчик из заметок, запиши номер
следующего прохода, дефект и основание исправления. После дефектов исправь
код через `edit_file` и выполни проход 2, затем при необходимости 3.
Перерендеривай только проблемные кадры и кадры, на которые могла повлиять
правка; ранее успешно проверенные кадры неизменённых сцен остаются зачтёнными.
Выборку из 4–8 можно дополнить неизменёнными опорными кадрами.

Успех — каждый выбранный опорный кадр актуальной версии просмотрен,
все пункты чек-листа соблюдены, известных непроверенных дефектов не осталось.
Если проход 3 неуспешен, упрости композицию один раз (убери эффект, замени
сложную анимацию, сократи длительность) и заново выбери и просмотри кадры
упрощённой версии. Это обязательная проверка после упрощения, а не сброс
счётчика: новые циклы исправлений не начинай. Если дефекты остаются,
остановись и объясни неудачу; полный рендер и заявление о готовности запрещены.
При успешном упрощении перечисли пользователю отличия от просьбы.

## 6. Полный рендер и файл

Только после успешной проверки кадров запусти полный рендер без `--frames`
по `remotion-render` и `sandbox-environment`. Рендерит основной агент;
одновременно выполняется одна команда рендера. Дождись успешного завершения
фонового задания, если `bash` вернул `running`.

Проверь существование и ненулевой размер результата, затем:

```sh
npx remotion ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,duration:format=duration -of default=nw=1 <файл>
```

Должна быть видеодорожка; её ширина и высота совпадают с композицией,
длительность — с `durationInFrames / fps` с допуском одного кадра.
Если длительность потока `N/A`, используй `format.duration`. Для ролика
с озвучкой обязательна аудиодорожка. Ошибка рендера или проверки файла —
не готовый ролик: действует общий предел попыток из раздела «Неудача»;
любая правка композиции снова требует проверки кадров до повторного рендера.
Обнови «Последний рендер» в `NOTES.md` только для проверенного файла.
Отправь Markdown-ссылку с путём от `/workspace`, включая каталог проекта.

Для озвучки выполни также проверку `voiceover/references/remotion.md`:
аудиодорожка не короче видео минус 100 мс, конец исходного аудио последней
сцены отстоит от конца видео на 0,5 с ±100 мс.

Справочник CLI: [render](https://www.remotion.dev/docs/cli/render.md),
[still](https://www.remotion.dev/docs/cli/still.md),
[ffprobe](https://www.remotion.dev/docs/cli/ffprobe.md).
