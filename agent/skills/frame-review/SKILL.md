# Проверка кадров

Проверяй изображение глазами через `read_file`. Исходный код, успешный код
возврата и прошлые записи в `NOTES.md` не заменяют просмотр.

Проверка — отдельный этап с воротами. Пока она не пройдена, полный рендер
не начинается, а ролик не называется готовым.

## 1. Числа до кадров

Прочитай `NOTES.md` проекта и исходники композиции. Возьми из кода фактические
`from`, `durationInFrames`, интервалы анимаций и переходов, а не текст заметок.
Номера строк в ответе `read_file` не входят в текст файла: не удаляй их правкой.

Запиши в `NOTES.md` до первого рендера кадров:

- таблицу сцен: текст, кадр начала, кадр конца, оба включительно;
- для каждой анимации — интервал в кадрах и кадр установившегося состояния
  (`конец входа + 1`, если он внутри сцены);
- перекрытия сцен и длину каждого перехода;
- итоговый список опорных кадров с причиной выбора и номером прохода.

Начало и конец сцены — абсолютные номера. Секунды переводи в кадры как
`round(секунды × fps)`. Конец сцены — `start + durationInFrames − 1` с учётом
вложенных смещений и перекрытий; сверь результат с таблицей сцен.

**Готово, когда** список кадров и числа сцен записаны в заметках. Без этой
записи рендер кадров не начинается.

## 2. Какие кадры выбрать

За проход выбери **4–8 разных кадров**. Кандидаты:

- `0` и последний `durationInFrames − 1`;
- каждая сцена `[start, end]`: `start + round(0.25 × (end − start))`
  и `start + round(0.85 × (end − start))`;
- середина каждого реального перехода;
- самый плотный кадр — максимум одновременно видимых текста и элементов;
- для субтитров — кадр с самой длинной страницей и кадр на границе двух фраз
  по таймингам `voiceover`;
- кадры на вычисленных границах анимаций: конец входа и начало выхода.

Кадр на 85 % — выборочная точка, а не доказательство конечного состояния.
Если установившегося интервала нет, проверяй фактическую границу анимации
внутри сцены. Для проверки конечного состояния выбери реальный кадр после
завершения входа и до начала выхода.

Округли номера, ограничь диапазоном композиции, убери дубликаты. Если весь
ролик короче четырёх кадров, посмотри все его кадры. Если кадров меньше
четырёх, добавь равномерные точки ролика. Если больше восьми, оставляй
в таком порядке:

1. Кадр `0`, последний, самый плотный; при субтитрах — самая длинная страница
   и граница двух фраз. Дубликаты занимают одно место.
2. Кадры изменённых сцен и затронутых переходов: сначала ранее проблемные,
   затем новая вёрстка и самый плотный текст; при равном риске — по хронологии.
3. Кадры около 25 % сцен: при `m` сценах и `k` местах индексы
   `round(j × (m − 1) / (k − 1))`, `j = 0…k − 1`; при `k = 1` — середина.
4. Около 85 % следующей сцены и середину следующего перехода по очереди.

Контрольную выборку из просьбы пользователя или оценки не заменяй своей.

**Готово, когда** выбрано от четырёх до восьми разных номеров, каждый
с причиной, список отсортирован по возрастанию и записан в заметки.

## 3. Рендер кадров

Все команды — из каталога проекта. Каждый запуск пишет в новый каталог;
старые кадры не удаляй командой `rm -rf`.

```sh
npx remotion render <вход> <композиция> out/frames-N --frames=<список> --image-format=jpeg --jpeg-quality=90
ls out/frames-N
```

Для одного кадра допустим `remotion still` с тем же `--image-format=jpeg`.
Имена `element-<кадр>.jpeg` дополняются нулями до ширины наибольшего номера:
`0,30,89` даёт `element-00.jpeg`, `0,30,899` — `element-030.jpeg`. Бери
настоящие имена из `ls` и не смотри кадры предыдущей версии.

Дальше отдельным шагом проверь пиксели **всех** кадров и дождись результата:

```sh
python3 "$HOME/.agents/skills/frame-review/scripts/check-frames.py" out/frames-N/*.jpeg
```

Для PNG укажи `*.png`, при повторной проверке перечисли актуальные файлы явно.
Скрипт только читает изображения. Код 1 — однотонный или почти чёрный кадр,
код 2 — ошибка чтения. При коде 1 запиши дефект, исправь композицию и перерендери
затронутые кадры в новый каталог; неудачная проверка расходует проход из раздела 6.

**Готово, когда** скрипт вернул 0 для всех актуальных кадров. Нормальный
диапазон пикселей означает отсутствие пустого кадра, а не качество ролика.

## 4. Просмотр

Вызови `read_file` для каждого выбранного файла, можно параллельно, и дождись
всех ответов. Для каждого кадра проверь и запиши числа:

- текст целиком внутри кадра, без обрезки, случайных переносов и опечаток;
- безопасная зона: при ширине 1080 px — минимум 80 px по бокам и 100 px
  сверху и снизу; заголовок не меньше 84 px, поясняющий текст — 44 px.
  Числа масштабируй на `ширина композиции / 1080`;
- элементы не перекрываются, текст контрастен и читается на фоне;
- нет пустых и чёрных кадров, «тофу» вместо букв, пропавших эмодзи
  и сломанных изображений;
- на вычисленных границах анимация показывает задуманное: проверь реальные
  кадры конца входа и начала выхода;
- соотношение сторон и размеры совпадают с заказом;
- субтитры — не больше двух строк в безопасной зоне, размер не ниже нормы
  поясняющего текста, есть контрастная подложка и выделение текущего слова;
  сверь кадр со временем слова, допуск ±150 мс.

`read_file` показывает PNG, JPEG, GIF и WebP не больше **3 МиБ** и **8000 px**
по стороне; иначе возвращает ошибку. При стороне больше 4000 px добавь
к рендеру кадров `--scale=0.5`. PNG — только для резкости мелких деталей,
и тогда сначала проверь `stat -c%s <файл>`. Масштаб проверочных изображений
не меняет заказанное разрешение видео.

**Готово, когда** каждый кадр просмотрен и по нему записаны числа.

## 5. Отчёт

Заполни в `NOTES.md` таблицу «Проверка кадров» из
[шаблона заметок](references/notes-template.md): кадр, кегль заголовка и его
норма, отступ сверху и его норма, обрезка и наложение, вывод. Если в кадре нет
заголовка или поясняющего текста, поставь прочерк: таблица остаётся заполненной
по каждому кадру. Числа бери из исходника и пересчёта, а не из впечатления.

Отчёт честный по устройству:

- проверка не пройдена — так и напиши, с выводом команды или строками дефектов;
- шаг пропущен — назови его;
- ролик готов только тогда, когда кадры и файл проверены.

Формулировку «дефектов нет» пиши только после заполненной таблицы, в которой
каждый замер не меньше нормы. Пустая таблица и «всё хорошо» — это не отчёт.

**Готово, когда** таблица заполнена по каждому кадру, а итог совпадает с ней.

## 6. Исправление и предел попыток

При квадратах вместо букв сначала прочитай точную строку из исходника: сверь
её символы, слова и язык с задуманным текстом. Исправь случайные символы или
чужое слово через `edit_file`; шрифт и его загрузку проверяй, только если
исходная строка верна. После исправления просмотри заново отрендеренный кадр.

У проверки кадров и правила «три попытки исправить одну проблему» один счётчик
в `NOTES.md`: **не больше трёх проходов**. Первый набор кадров — проход 1,
включая проверку пикселей и просмотр. Перед каждым следующим рендером прочитай
счётчик, запиши номер прохода, дефект и основание исправления.

После дефектов исправь код через `edit_file` и выполни проход 2, затем при
необходимости 3. Перерендеривай только проблемные кадры и кадры, на которые
могла повлиять правка; успешно проверенные кадры неизменённых сцен остаются
зачтёнными. Выборку из 4–8 можно дополнить неизменёнными опорными кадрами.

Успех — каждый выбранный кадр актуальной версии просмотрен, все пункты
чек-листа соблюдены, известных непроверенных дефектов нет.

Если проход 3 неуспешен, упрости композицию один раз: убери эффект, замени
сложную анимацию, сократи длительность. Выбери и просмотри кадры упрощённой
версии заново: это обязательная проверка, а не сброс счётчика и не новый цикл.
Если дефекты остаются, остановись и объясни неудачу; полный рендер и заявление
о готовности запрещены. При успешном упрощении перечисли пользователю отличия
от просьбы.

**Проверку подменять нельзя:** уменьшать выборку ниже четырёх, заменять кадры
предыдущей версии, считать успешный рендер просмотром или статистику
визуальной проверкой.

**Готово, когда** все кадры актуальной версии просмотрены и таблица отчёта
заполнена.

## 7. Рендер и проверка файла

После успешной проверки кадров выполни выбранную в инструкциях ветку:
черновик или финал. Этот навык проверяет файл, а не разрешает переход к финалу.
Команда без `--frames` создаёт видео; размер и качество задаёт выбранная ветка.
Рендерит основной агент, одна команда за раз. Если `bash` вернул `running`,
дождись успешного завершения задания.

У проверки два результата: до видеорендера — просмотренные кадры композиции,
после него — проверенный файл. Изменение композиции требует новых кадров.
Извлечение кадров из MP4 и повторный просмотр в уменьшенном разрешении —
дополнительная диагностика, а не обязательная проверка: её отказ не доказывает
дефект видео и не отменяет успешные проверки.

Проверь существование и ненулевой размер (`test -s <файл>`, `stat` или
размерный `ls`), затем:

```sh
npx remotion ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,duration:format=duration -of default=nw=1 <файл>
```

Должна быть видеодорожка; размеры финала совпадают с композицией, черновика —
с размерами после `--scale`; длительность — `durationInFrames / fps` с допуском
один кадр. Если длительность потока `N/A`, используй `format.duration`. Для
ролика с озвучкой обязательна аудиодорожка.

Ошибка рендера или проверки файла — не готовый ролик: действует общий предел
попыток. Любая правка композиции снова требует проверки кадров до повторного
рендера. Обнови «Последний рендер» в `NOTES.md` только для проверенного файла.

Перед ссылкой сверь доказательства последней версии: просмотр кадров, успешный
рендер, ненулевой размер, потоки и длительность, а при музыке — раздельные
уровни и пик смеси. Неудачный замер не заменяй оговоркой рядом с «готовым».

Ссылка указывает путь от `/workspace`, включая каталог проекта.

Для озвучки выполни также `voiceover/references/remotion.md`: аудиодорожка
не короче видео минус 100 мс, конец последней сцены отстоит от конца видео
на 0,5 с ±100 мс.

Справочник CLI: [render](https://www.remotion.dev/docs/cli/render.md),
[still](https://www.remotion.dev/docs/cli/still.md),
[ffprobe](https://www.remotion.dev/docs/cli/ffprobe.md).
